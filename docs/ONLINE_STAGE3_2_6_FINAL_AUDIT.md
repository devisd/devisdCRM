### Подтверждено без замечаний

- **Миграция.** Каждое поле совпадает с Zod по обязательности, значениям по умолчанию, первичным и внешним ключам (`RESTRICT`/`CASCADE`), уникальности номера, индексам под реальные запросы и CHECK.
- **Unicode и эмодзи.** `utf8mb4` у всех таблиц и текстовых столбцов (идентификаторы — `ascii`), `SET NAMES utf8mb4` в миграции, `charset=utf8mb4` в DSN.
- **Валидация.** Формы и `backupFileSchema` используют те же константы и схемы.
- **PHP API по исходникам.** Корректно разобраны 404, 405 с `Allow`, 400, `HEAD` без тела, 503 для конфигурации и БД, 500 без утечек. Исправления аудита 3.2.1 на месте: перехват warnings драйвера MySQL, ограничение `open_basedir`, запрет `;` в DSN, отказ при приватном коде внутри document root, предварительное кодирование JSON. Логи вне webroot, сообщения драйвера БД в лог не попадают.

### Поля без симметричной проверки в PHP API

В PHP вообще нет маршрутов записи, поэтому проверки нет ни для одного поля. Когда появится CRUD, нужно повторить:

- 255 символов: `name`, `contactName`, `phone`, `email`, `telegram`, `maxContact`, `source`, `title`, название позиции;
- 64 символа: `unit`;
- 20 000 символов: `otherContact`, `notes`, `description` у заказа и позиции, `comment`;
- `number` в диапазоне 1…4 294 967 295 и `sortOrder` в диапазоне 0…4 294 967 295;
- остальные правила Zod: деньги, количество, UUID, перечисления, даты.
