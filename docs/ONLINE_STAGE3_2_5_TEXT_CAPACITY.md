# Этап 3.2.5. Вместимость SQL для длинных текстов

**Ветка:** `feature/online-migration`
**Дата:** 2026-10-25
**Commit / push / deploy / SQL на сервере:** не выполнялись.

---

## 1. Причина изменения

На этапе 3.2.4 выяснилось, что Zod 4 считает длину строк для `.max()` в кодовых точках Unicode (`docs/ONLINE_STAGE3_2_4_IMPLEMENTATION.md`, раздел 0, п. 3; риск R1).

Лимит длинных текстов — 20 000 кодовых точек. Символ вне BMP (эмодзи и т. п.) занимает в UTF-8 4 байта:

- 20 000 × 4 = **80 000 байт** — в худшем случае;
- `TEXT` вмещает **65 535 байт** — строка, прошедшая Zod, могла не поместиться в столбец;
- `MEDIUMTEXT` вмещает **16 777 215 байт** — запас более чем в 200 раз.

Принятое решение: **сохранить лимит Zod 20 000 и перевести длинные поля в `MEDIUMTEXT`.** В задании оно названо «вариант A»; в таблице R1 отчёта 3.2.4 тот же подход значился как вариант «б» (а «а» там — снижение лимита до 16 383). По содержанию решение однозначно, реализовано оно.

## 3. Почему лимиты Zod не изменились

- 20 000 символов — согласованное продуктовое ограничение (вариант C); причина расхождения была в вместимости столбца, а не в самом лимите.
- Снижение до 16 383 сократило бы допустимый текст для всех пользователей ради редкого крайнего случая (заметка почти целиком из эмодзи).
- Короткие лимиты (255 и 64) и числовые диапазоны к проблеме не относятся: для `VARCHAR(n)` MySQL тоже считает символы, а не байты, поэтому Zod и MySQL уже совпадают.

`src/lib/validation/schemas.ts`, формы и `backupFileSchema` **не изменялись** на этом этапе.

## 6. Оставшиеся риски

| # | Риск | Комментарий |
|---|------|-------------|
| R1 | Тип столбца не проверен на реальном MySQL | Миграция ещё не импортировалась. `MEDIUMTEXT` поддерживается MySQL 8 и MariaDB; проверить при импорте через phpMyAdmin. |
| R2 | PHP API пока не валидирует длину | При реализации CRUD — `mb_strlen()` ≤ 20 000 (кодовые точки, как в Zod) и 422 `validation_error`. Проверка байтов не нужна: 80 000 байт помещаются в `MEDIUMTEXT`. |
| R3 | `max_allowed_packet` | Одна запись с несколькими полями по 80 000 байт — порядка сотен КБ; типичное значение `max_allowed_packet` в MySQL 8 — 64 МБ. Не проверено на хостинге. |
| R4 | Реальные бэкапы не проверены | На этапе 3.2.3 в проекте их не было; совместимость с пользовательскими данными не подтверждена. |
| R5 | Нестрогий `sql_mode` | Для `MEDIUMTEXT` обрезание в пределах лимита Zod невозможно, но `sql_mode` по-прежнему стоит проверить для `VARCHAR` (`SELECT @@sql_mode;`). |
