## 5. Свойства сценариев

### A — подготовка

- Исходник берётся только по абсолютному пути `C:\Github\devisdCRM\tools\hosting-diagnostic.php`; SHA-256 сверяется с закреплённым значением и выводится как идентификатор версии. После любого изменения исходника хеш в сценарии A нужно обновить и повторить тесты.
- Если в `%LOCALAPPDATA%` есть любой объект `DevisDiag-*` — «СТОП» до создания чего-либо; чужие каталоги не удаляются.
- Ключ: 32 байта из `RandomNumberGenerator` → 64 hex. Не выводится, не попадает в аргументы и сообщения об ошибках.
- Рабочий каталог `DevisDiag-<8 hex>`; ACL: наследование отключено, доступ только текущему пользователю; результат проверяется через `Get-Acl`.
- Сначала `key.txt` (ASCII, без BOM и перевода строки), затем копия; обе записи — `CreateNew` (без перезаписи).
- Копия проверяется побайтно: совпадает с исходником везде, кроме строки `const DIAG_KEY = '…';`.
- При ошибке удаляется только созданное этим запуском (сначала файлы, затем пустой каталог). Если удалить не удалось — выводятся только безопасные имена оставшегося.
- Параметр `-TestFault` предназначен только для локальных тестов (искусственный сбой); при ручном запуске не задаётся.

### C — один запрос

- `curl.exe` ищется через `Get-Command`; выводится фактический путь. `curl.exe --disable --version` должен показать Schannel или OpenSSL, иначе «СТОП».
- Первый аргумент curl — `--disable`: пользовательские `.curlrc`/`_curlrc` не читаются.
- URL: только константа `https://crm.devisd.online/` + имя, строго соответствующее `^diag-[0-9a-f]{32}\.php$`. В рабочем каталоге должны быть ровно `diag-…php` и `key.txt`; `key.txt` — ровно 64 hex-байта.
- Параметры curl: `--proto =https --tlsv1.2 --noproxy * --silent --show-error --include --connect-timeout 10 --max-time 30 --data-urlencode key@<путь к key.txt>`. Нет `-k`, `-L`, `--retry`, трассировки, `-o`/`-D`. Ключ в командной строке не появляется — только путь к файлу.
- curl запускается через `System.Diagnostics.Process`: все аргументы экранируются (сборка mingw иначе раскрыла бы `*`), stderr curl не выводится — только код и краткая расшифровка.
- Разбор ответа: пропускаются только начальные `1xx` (кроме `101`); финальный статус должен совпадать с `%{http_code}`; ещё один HTTP-блок в теле — «СТОП».
- «СТОП», если: ненулевой код curl (тайм-аут, TLS, обрыв), не-200, `Location`, не-JSON `Content-Type`, невалидный JSON, `ok` не `true` (bool), `checks` не массив или пуст, у элемента нет корректного `id`, `result` не из `PASS/FAIL/SKIP/INFO`, лишние поля, `summary` не из `PASS/FAIL/SKIP/INFO` с целыми значениями, ключ или признаки путей/ошибок PHP в ответе.
- Печатаются только `id`, `result` и `value`, прошедшие белый список: простые токены, маски `<home>`, `<docroot>`, `<home>/devis-crm`, `<…>/<subpath>`, системные префиксы `/tmp/<subpath>` и т. п. Любое другое значение (например, `C:\…`, `/srv/…`, 64 hex) — «СТОП» без вывода значения. Сырое тело не выводится и не сохраняется.
- Серверный файл не удаляется.

**Решение по прокси.** curl не использует системные настройки прокси Windows, только переменные окружения и параметры. Сценарий передаёт `--noproxy *` и **останавливается**, если задана `HTTPS_PROXY` или `ALL_PROXY`: молча обходить прокси, который может быть нужен сети, нельзя, а запрос через него — отдельное решение пользователя. Переменные окружения сценарий не меняет.

**Чего не решает `--disable`.** Он отключает только файлы конфигурации curl. Переменные окружения (прокси, `SSLKEYLOGFILE`, `CURL_CA_BUNDLE`, `SSL_CERT_*`, `CURL_SSL_BACKEND`) сценарий проверяет отдельно. Доверенные корневые сертификаты Windows (Schannel), корпоративный TLS-перехват, групповые политики, журналирование PowerShell (transcription, script block logging) и средства мониторинга сценарий не контролирует.

### D — локальная очистка

- Ровно один объект `DevisDiag-*` непосредственно в `%LOCALAPPDATA%`; это обычный каталог (не файл, не ссылка/junction) с именем `^DevisDiag-[0-9a-f]{8}$`.
- Внутри — ровно `diag-<32 hex>.php` и `key.txt` (обычные файлы). Любой посторонний объект, отсутствие `key.txt`, неверные имена → «СТОП», ничего не удаляется.
- Перед удалением — имена файлов и два подтверждения: `УДАЛЁН` и `ДА` (точное совпадение). Неверный ввод или отсутствие ввода → ничего не удаляется.
- Удаление поштучно (`[IO.File]::Delete`), после каждой ошибки — остановка; каталог удаляется только пустым через `[IO.Directory]::Delete($dir, $false)`. `Remove-Item -Recurse` не используется.
- Повторный запуск после очистки: «Рабочий каталог DevisDiag-* не найден», код 0.

## 6. Условия остановки

- Сценарий A вывел «СТОП» или хеш не совпал → не продолжать.
- Разрешение на серверную диагностику не получено → не загружать; локальные файлы удалить сценарием D (раздел 4, шаг 3).
- Загруженный файл не тот (имя, размер, каталог) → удалить его (шаг 6), не запускать C.
- Сценарий C вывел «СТОП» (любой причины) → не повторять, сразу шаг 6.
- В выводе C обнаружены пути, ключ или сообщения PHP → не публиковать вывод, сразу шаг 6.
- Серверный файл не удаётся удалить → раздел 7.

## 7. Если серверный файл не удаётся удалить

1. Не запускать C повторно, не запускать D (локальная копия с точным именем нужна для сверки).
2. Попробовать снова через «Менеджер файлов» ISPmanager; при наличии FTPS — удалить этот один файл через FTPS.
3. Если удалить нельзя, но можно изменить файл: очистить его содержимое встроенным редактором ISPmanager или выставить права `000` — так PHP перестанет его выполнять. **Не переименовывать** в не-`.php`: исходник с ключом станет скачиваемым.
4. Обратиться в поддержку REG.RU с точным именем файла.
5. До удаления файл остаётся доступен любому, кто знает ключ и имя; ключ одноразовый и бесполезен после удаления файла.

Для теста TLS заменяется только `$BaseUrl` (`https://localhost:<порт>/`), `$Proto = '=https'` остаётся рабочим. Каждый дочерний процесс получает собственный `LOCALAPPDATA` во временном каталоге; переменные прокси удаляются из его окружения.

## 9. Ограничения локального тестирования

- Реальный TLS с `crm.devisd.online` (цепочка, проверка отзыва через Schannel, HTTP/2) не проверялся.
- Поведение Apache/nginx/FastCGI, `.htaccess` корня сайта, реальные заголовки и статусы — только на сервере.
- Вывод `hosting-diagnostic.php` на хостинге может содержать значения, которых нет в локальном прогоне (например, иные записи `open_basedir`). Если белый список C их не пропустит, C честно остановится («недопустимый формат») — это безопасный, но возможный исход; разбирать его нужно без публикации значения.
- Тест выполнялся в неинтерактивных процессах с перенаправленным вводом/выводом. В обычной консоли подтверждения D вводятся с клавиатуры; кодировка консоли проверена только на кодовой странице OEM этой машины.
- Защита от средств мониторинга Windows, журналирования PowerShell по политике и администратора системы не обеспечивается.
- Удаление серверного файла и его отсутствие подтверждаются только вручную.
